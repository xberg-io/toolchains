# toolchains

The xberg-io toolchain baseline for [mise](https://mise.jdx.dev): one set of tool and language versions that
every repository installs locally and in CI.

## Contents

| Path | Purpose |
|---|---|
| `baseline.toml` | Canonical versions, in mise `[tools]` syntax. Renovate bumps them here first. |
| `scripts/toolchains.py` | `check` reports drift from the baseline; `sync` rewrites a repository's pins to it. Standard library only, Python 3.11+. |
| `tasks/` | Shared mise file tasks that consuming repositories reference by tag (see below). |
| `default.json` | Renovate preset for consumers: turns off upstream bumps for baseline tools, groups repo-owned ones. |

## Consuming repositories

A repository commits:

- `mise.toml` with the tools it needs, using the baseline's exact key, version and table options (`node = "26.12.1"`,
  `"github:Goldziher/poly" = "0.29.0"`). An alias of a baseline tool (`nodejs`, `core:node`, `aqua:…`) is drift;
- `mise.lock`, generated by `mise lock`, covering `linux-x64`, `linux-arm64`, `macos-arm64` and `windows-x64`;
- `rust-toolchain.toml` for Rust, which stays authoritative for components and targets. Declaring `rust` in
  `mise.toml` is an error; the file's `channel` is checked against the baseline's `rust`;
- `toolchains.toml` recording the baseline tag it follows, and any override:

```toml
baseline = "v1.0.0"

[overrides.node]
version = "22.20.0"
reason = "engines floor smoke test runs on the oldest supported Node"

[overrides."github:Goldziher/poly"]
version = "0.28.4"
reason = "example: hold the previous release until a regression fix ships"
```

Only `mise.toml` is read; profile files such as `mise.ci.toml` are not checked.

Tools the baseline does not list (for example `wasm-bindgen-cli`, which must match `Cargo.lock`) are owned by the
repository. Renovate updates them when the repository extends `github>xberg-io/toolchains`.

## Moving to a new baseline

```sh
git clone --depth 1 --branch v1.1.0 https://github.com/xberg-io/toolchains /tmp/toolchains
python3 /tmp/toolchains/scripts/toolchains.py sync --baseline /tmp/toolchains/baseline.toml --ref v1.1.0
mise lock
python3 /tmp/toolchains/scripts/toolchains.py check --baseline /tmp/toolchains/baseline.toml
```

`check` exits 1 on drift and 2 when nothing could be checked: a missing `mise.toml`, or no declared tool covered by
the baseline. It lists the repository-owned tools it skipped. It also exits 1 when the repository root still holds
go-task files, since the org runs its tasks with mise: a `Taskfile.yml`, `Taskfile.yaml`, `Taskfile.dist.yml` or
`Taskfile.dist.yaml` in any letter case, or a `.task/` directory. In a git checkout only tracked files count, so an
ignored `.task/` cache passes; elsewhere the files on disk are checked. `sync` writes nothing when any pin cannot be rewritten
(for example a `[tools.node]` subtable) or when table options differ from the baseline; fix those by hand.

## Shared tasks

Tasks that every repository needs with the same body live under `tasks/` and are referenced by tag, so a fix
lands once and repositories pick it up on the next baseline move:

```toml
[tasks."governance:hooks:install"]
file = "https://raw.githubusercontent.com/xberg-io/toolchains/v1.5.0/tasks/governance/hooks-install.sh"
```

Use the same tag as `toolchains.toml`. Keep one-line tasks (`governance:check`, `lint`) inline in `mise.toml`.

| Task | File |
|---|---|
| `governance:hooks:install` | `tasks/governance/hooks-install.sh`: allow the system hook channel in `poly.local.toml`, then `poly hooks install` |
| `alef:pin:check` | `tasks/alef/pin-check.sh`: fail unless the alef on PATH is the clean release `alef.toml` pins |
| `alef:regenerate` | `tasks/alef/regenerate.sh`: run every alef generator that writes the version |
| `alef:verify:strict` | `tasks/alef/verify-strict.sh`: `alef verify`, failing on drifted frozen paths too |
| `version:show` | `tasks/version/cargo.sh`: print the workspace version from `Cargo.toml` |
| `deps <update\|upgrade> [lang]` | `tasks/deps/refresh.sh`: refresh one ecosystem or every one in `DEPS_LANGS`; repository specifics in the task's `env` (`DEPS_<LANG>_DIR`, `DEPS_NODE_DIRS`, `DEPS_RUST_MANIFESTS`) |

## Lock gaps

CI locks the whole baseline for all four platforms. These cannot be locked and are allowed by name: `dotnet` and
`rust` (installed by script, no checksummed artifact), `aws-cli`, `bats` and `ruby` on Windows, `cargo-sort` on
linux-arm64. Jobs on those platforms keep their existing setup action for that tool.

## Changing the baseline

Edit `baseline.toml`, keep `default.json`'s disabled list equal to its keys (a test enforces this), and tag a
release. Patch versions follow the newest patch of the line in use; moving a minor or major line is a reviewed
change.
